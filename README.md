# Togedy AI Chatbot

대학 입시요강을 기반으로 질문에 답하는 Flask 기반 RAG 챗봇입니다. 질문에서 대학명, 전형, 핵심어를 추출한 뒤 대학별 모집요강에서 관련 페이지를 검색하고 LLM으로 답변을 생성합니다.

## 처리 흐름

1. KoBERT NER 모델로 `UNI`, `TYPE`, `KEYWORD` 추출
2. Gemini를 이용해 복수 개체와 검색 조건 보정
3. 대학·전형별 추출 문서에서 TF-IDF 기반 관련 페이지 검색
4. 검색 문맥을 바탕으로 OpenAI 모델이 최종 답변 생성
5. 답변과 함께 사용한 문서 및 페이지 정보 반환

## 디렉터리 구성

```text
.
├── main.py                    # Flask API 진입점
├── settings.py                # 환경변수와 프로젝트 경로 설정
├── generate_answers.py        # 단일/후속 질문 답변 파이프라인
├── extract_all.py             # NER 모델 통합
├── search_and_export.py       # 페이지 검색과 결과 구성
├── config/major_aliases.json  # 대학별 요청 학과명과 실제 모집단위 관계
├── document_retrieval/        # TF-IDF 검색 모듈
├── KORBERT_NER_UNI/           # 대학명 NER 모델
├── KORBERT_NER_TYPE/          # 전형 NER 모델
├── KORBERT_NER_KEYWORD/       # 핵심어 NER 모델
├── university/                # 대학별 PDF, 텍스트, 표 데이터
├── llm/                       # LLM 클라이언트와 프롬프트
├── ocr/                       # PDF 텍스트·표 추출 도구
└── app/                       # 이전 파이프라인 코드(현재 진입점 아님)
```

## 로컬 실행

Python 3.11 환경을 권장합니다.

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python main.py
```

`.env`에 최소 `GOOGLE_API_KEY`와 `OPENAI_API_KEY`를 설정해야 전체 답변 파이프라인이 동작합니다. 포트와 모델 등 나머지 설정은 `.env.example`을 참고하세요.

서버가 시작되면 다음 엔드포인트를 사용할 수 있습니다.

- `GET /health`: 서버 상태와 NER 모델 로딩 여부 확인
- `POST /answer`: 입시 질문 처리

NER 모델은 서버 시작 시가 아니라 첫 `/answer` 요청에서 한 번만 로딩됩니다. `/health`는 무거운 모델을 로딩하지 않습니다.

## API 예시

최초 질문:

```powershell
$body = @{
  first = $true
  question_1 = "연세대학교 수시 모집인원을 알려줘"
} | ConvertTo-Json

Invoke-RestMethod -Method Post -Uri http://localhost:5000/answer `
  -ContentType application/json -Body $body
```

후속 질문에서는 직전 질문과 서버가 반환한 `NER` 값을 함께 전달합니다.

```json
{
  "first": false,
  "question_1": "연세대학교 수시 모집인원을 알려줘",
  "question_2": "컴퓨터과학과만 알려줘",
  "NER": {
    "UNI": ["연세대학교"],
    "TYPE": ["수시"],
    "KEYWORD": ["모집인원"]
  }
}
```

## 개발 확인

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest
```

모델 파일과 대학별 원본 데이터가 크므로 새 환경에서는 저장소 체크아웃과 최초 모델 로딩에 시간이 걸릴 수 있습니다.

## 관리 원칙

### 검색·답변 근거 검증

- 검색은 띄어쓰기 차이와 제출서류/구비서류 같은 항목 표현을 함께 고려합니다. 관련 키워드가 없는 페이지와 목차는 제외하고, 일반 입시 질문에서 기숙사·장학·서식 페이지가 우선되지 않도록 처리합니다.
- `question_plan.py`에서 대학·수시/정시·학과·요청 항목·조건을 한 번 정리하고 검색과 답변에 함께 전달합니다. 복수 전형과 항목을 보존하며, 일정·제출서류·영어 환산표는 공통 안내 페이지도 검색합니다.
- `llm/document_pipeline.py`는 문서에 부여한 근거 ID로 문장을 생성하고 `llm/evidence.py`에서 ID, 숫자, 모집단위와 인원 관계를 검사합니다. 상담·추가 정보 요청·일상 대화는 별도로 처리합니다. 외부 API 응답 형식은 유지합니다.
- 근거 ID 하나에 선택된 PDF 한 페이지 전체를 담아 표의 제목과 마지막 행이 서로 다른 구간으로 잘리는 것을 방지합니다. 복합 질문은 항목별로 생성·검증하며, 내부 `stats.coverage`에 답변 여부를 남깁니다. 이 값은 의미적 정답 판정이 아닙니다.
- `llm/table_evidence.py`는 열 제목과 인원 합계가 일치하는 단순 모집인원 표를 직접 읽습니다. 구조가 불명확한 표는 직접 계산하지 않습니다. 미대 검색에서는 비미술 모집단위와 미술 제외 조건을 거르고, 반영요소와 퍼센트가 원문에서 직접 연결되는지 추가 검사합니다.
- 영어 등급별 환산표는 1~9등급과 대응하는 공통 점수 9개가 명시된 형식만 직접 읽습니다. 행이 부족하거나 복수 페이지의 점수가 충돌하면 직접 답변하지 않습니다.
- `config/reviewed_admission_facts.json`은 원본 PDF를 확인한 미술 전형의 소규모 구조화 자료입니다. 대학·전형·모집단위·모든 단계·최종 반영비율·유의사항·원문 페이지·해시를 보관합니다. `llm/reviewed_facts.py`가 원문 해시, 핵심 문구, 단계별 합계와 질문 조건을 검사한 뒤 확인된 사례로 안내합니다. 전체 대학 전형을 망라하는 자료가 아닙니다.
- 구조화 자료 추가·갱신 시 원본 PDF의 병합 셀, 모든 단계와 지원 조건을 직접 검토해야 합니다. 원문이 바뀌었다는 이유만으로 해시만 갱신하면 안 됩니다. 검토 전에는 기존 자료의 해시 불일치 상태를 유지해 사용을 막습니다.
- `config/reviewed_topic_tables.json`과 `llm/reviewed_topics.py`는 제출서류의 예외, 전형의 적용 계열, 논술 최저, 서류평가 열, 공통 일정을 같은 방식으로 관리합니다. 주제·대학·전형·모집단위와 제외 조건이 맞는 기록만 사용하며, 여러 출처 중 하나라도 바뀌면 기록 전체를 사용하지 않습니다. 수동 검토 자료이므로 새 대학·전형에 대한 자동 일반화는 하지 않습니다.
- 생성 문장은 `llm/semantic_review.py`에서 조건·적용 범위를 원문과 한 번 더 비교합니다. 거절된 내용은 최대 한 번만 다시 생성·검증하며 검증 형식 오류는 승인으로 처리하지 않습니다. 이 모델 검토도 오류를 놓칠 수 있으므로 확인된 복합 표는 구조화 자료를 우선합니다.
- `llm/major_resolution.py`는 문서에서 찾지 못한 모집단위명을 실제 표에 있는 유사 명칭과 비교해 확인 질문을 만듭니다. 후보를 자동으로 동일 학과로 간주하지 않습니다. 후속 질문에서 학과를 고치면 이전 요청 항목을 유지합니다.
- 검증을 통과하지 못한 문장은 제외하며, 근거가 전혀 없으면 확인하지 못했다는 안내를 반환합니다. 출처는 검증을 통과한 문장이 인용한 페이지로 제한합니다. 계산으로 새 숫자를 만드는 답변은 현재 검증 대상에서 제외합니다.
- 이 검사는 모든 문장의 의미나 복잡한 표의 행·열 관계까지 보장하지 않습니다. 지원자 유형과 세부 전형의 조건을 과도하게 일반화하거나 일부 요청을 놓칠 수 있습니다. LLM 응답 형식 오류와 불명확한 표는 보수적으로 보류하므로 실제 모델 평가가 별도로 필요합니다.
- `tests/test_retrieval_evidence.py`는 무관한 검색, 실제 문서의 오검색 사례, 잘못된 인용·숫자, 여러 대학 중 일부 검색 실패, 출처 페이지 일치를 검증합니다. LLM 호출은 테스트 대역을 사용합니다.
- `tests/test_question_pipeline.py`는 복수 조건 보존, NER 호출 횟수, 상담 분기, 근거 ID, 다른 모집단위 숫자, 실제 서울대 인원 표와 미대 조건 오적용을 검증합니다.
- 실제 API 평가는 `python evaluations/run_image_questions.py --output 새로운_파일명.json`으로 실행합니다. 기존 결과 파일을 덮어쓰지 않습니다. 테스트 통과율과 실제 답변 정확도는 서로 다른 지표입니다.
- `--ner-from 기존_평가.json`을 지정하면 동일 질문의 NER만 재사용하고 검색·생성·의미 검증은 새로 실행합니다. 결과의 `mode`와 `ner_source`에 이 차이를 기록합니다. 전체 NER를 다시 평가한 것으로 해석하면 안 됩니다.

### 저장소 관리

- 현재 운영 진입점은 루트의 `main.py`입니다.
- 파일 경로는 실행 위치가 아니라 저장소 루트를 기준으로 해석합니다.
- API 키와 개인 설정은 `.env`에만 두고 커밋하지 않습니다.
- 생성 결과와 캐시는 Git에 추가하지 않습니다.
- 일반적인 컴퓨터 계열 학과명 차이는 선택된 대학 모집요강에서 실제 모집단위를 자동 탐색합니다.
- 통합 모집 후 전공 선택처럼 단순 명칭 차이가 아닌 관계는 `config/major_aliases.json`에 대학 slug별 검색어와 관계 설명을 추가합니다.
- 입시 정보는 실제 서비스에 사용하기 전에 반드시 해당 대학의 최신 공식 모집요강과 대조합니다.

### 조건 검색과 후속 대화 검증

- `query_constraints.py`는 실기·수능의 이상/이하/초과/미만/정확한 비율을 해석하고 복합 조건과 0~100% 범위를 검사합니다. 질문에 1단계·2단계가 명시되면 해당 단계의 자료를 사용합니다.
- 제외·말고·빼고로 지정한 대학과 모집단위는 검색, 검토된 자료 선택, 생성 문장 검증에서 제외합니다. 비율이 없는 평가요소를 0%로 추정하지 않습니다.
- 세부 전형 변경은 그 전형에 맞는 수시·정시와 이전 요청 항목을 함께 보존합니다. 검토된 미술 전형의 빠른 반환은 복합 요청의 다른 항목을 생략하지 않도록 제한합니다.
- 검증 모델의 승인은 해당 주장이 인용한 근거 ID와 정확한 원문 인용이 있어야 통과합니다. 승인 누락이나 원문 재작성은 거절합니다. 인용 존재만으로 의미가 항상 정확하다는 보장은 없습니다.
- 일정 CSV는 항목명과 날짜가 원문에 같은 순서로 연속한 행만 직접 추출합니다. 여러 날짜 열, 빈 항목명, 다른 행의 날짜 교환은 추정하지 않습니다. 결과는 일정 발췌로 안내합니다.
- `evaluations/evaluate_new_question_scope.py`는 신규 28문항의 로컬 해석·표 선택 검사입니다. NER 모델과 외부 LLM을 평가하지 않으며 전체 답변 정확도 지표가 아닙니다. 자세한 적용·검증 내역은 [2026-10-10 보고서](evaluations/accuracy_notion_report_20261010.md)를 참고합니다.
